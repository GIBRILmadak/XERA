Tous les endpoints de l'API XERA1 qui accèdent à des données spécifiques à l'utilisateur nécessitent une authentification. Lorsque vous vous connectez à XERA1, la plateforme émet un **jeton d'accès** à courte durée de vie (un JWT). Incluez ce jeton dans l'en-tête `Authorization` de chaque requête vers un endpoint protégé. Les requêtes non authentifiées retournent immédiatement une réponse `401 Unauthorized`.

## Comment fonctionne l'authentification

Après une connexion réussie, XERA1 fournit une session qui contient un **jeton d'accès**. Chaque appel API ultérieur doit transporter ce jeton afin que le serveur puisse vérifier votre identité et limiter la réponse à votre compte. Le jeton est lié à votre session XERA1 : il n'accorde l'accès qu'aux données appartenant à cette session.

```text
Authorization: Bearer <votre-jeton-d-acces>
```

Le serveur valide le jeton à chaque requête. Si le jeton est valide, la requête est traitée. Si le jeton est expiré, manquant ou malformé, l'API retourne `401`.

## Obtenir votre jeton d'accès

Vous pouvez récupérer votre jeton d'accès de deux manières : depuis les outils de développement du navigateur (utile pour les tests) ou de manière programmatique via la session client XERA1 (recommandé pour les intégrations).

<Steps>
  <Step title="Connectez-vous à XERA1">
    Ouvrez [xera1.xyz](https://xera1.xyz) dans votre navigateur et connectez-vous avec vos identifiants.
  </Step>
  <Step title="Ouvrez les outils de développement et trouvez votre jeton de session">
    Ouvrez les outils de développement de votre navigateur (`F12` ou `Cmd+Option+I`), naviguez vers l'onglet **Application** et cherchez dans le **Stockage local** sous `https://xera1.xyz` l'entrée qui contient `auth-token`. Le champ `access_token` à l'intérieur de cette entrée est votre jeton Bearer.

    <Tip>
      Si vous ne le trouvez pas dans le Stockage local, vérifiez la section **Cookies** du même panneau : le jeton peut y être stocké selon la configuration de votre navigateur.
    </Tip>
  </Step>
  <Step title="Ou récupérez-le de manière programmatique depuis la session">
    Si vous construisez une intégration qui s'exécute dans un contexte authentifié aux côtés de l'application XERA1, récupérez la session de manière programmatique :

    ```javascript
    const { data: { session } } = await xera1.auth.getSession();
    const accessToken = session?.access_token;
    ```

    Cette approche retourne toujours le jeton actuel non expiré et est la méthode recommandée pour tout code s'exécutant au nom d'un utilisateur connecté.
  </Step>
</Steps>

## Utiliser le jeton dans les requêtes

Passez le jeton dans l'en-tête `Authorization` avec le schéma `Bearer` à chaque requête vers un endpoint protégé.

<CodeGroup>

```javascript JavaScript (fetch)
const { data: { session } } = await xera1.auth.getSession();

const response = await fetch('https://xera1.xyz/api/app/discover/users', {
  headers: {
    'Authorization': `Bearer ${session.access_token}`,
    'Content-Type': 'application/json'
  }
});

const data = await response.json();
```

```bash cURL
curl -X GET https://xera1.xyz/api/app/discover/users \
  -H 'Authorization: Bearer VOTRE_JETON_D_ACCES' \
  -H 'Content-Type: application/json'
```

```python Python (requests)
import requests

headers = {
    'Authorization': 'Bearer VOTRE_JETON_D_ACCES',
    'Content-Type': 'application/json'
}

response = requests.get(
    'https://xera1.xyz/api/app/discover/users',
    headers=headers
)

data = response.json()
```

</CodeGroup>

Remplacez `VOTRE_JETON_D_ACCES` par la valeur réelle du jeton de votre session. Pour les intégrations JavaScript, récupérez toujours le jeton dynamiquement depuis la session plutôt que de l'écrire en dur : les jetons expirent et doivent être rafraîchis.

## Expiration du jeton et rafraîchissement

Les jetons d'accès sont à courte durée de vie (généralement **une heure**). Lorsqu'un jeton expire, tous les appels API retournent `401 Unauthorized` jusqu'à ce que vous le rafraîchissiez.

**Rafraîchir le jeton manuellement :**

```javascript
const { data: { session }, error } = await xera1.auth.refreshSession();

if (error) {
  // La session n'a pas pu être rafraîchie : invitez l'utilisateur à se reconnecter
  console.error('Échec du rafraîchissement de la session :', error.message);
} else {
  const newAccessToken = session.access_token;
  // Utilisez newAccessToken pour les appels API ultérieurs
}
```

**Ou écoutez le rafraîchissement automatique du jeton** en utilisant les événements de changement d'état d'authentification : votre client recevra une nouvelle session chaque fois que le jeton est rafraîchi silencieusement :

```javascript
xera1.auth.onAuthStateChange((event, session) => {
  if (event === 'TOKEN_REFRESHED') {
    // session.access_token est maintenant le nouveau jeton
    updateStoredToken(session.access_token);
  }
  if (event === 'SIGNED_OUT') {
    // Effacez le jeton stocké et redirigez vers la connexion
    clearStoredToken();
  }
});
```

<Info>
  Les sessions XERA1 incluent un **jeton de rafraîchissement** à longue durée de vie aux côtés du jeton d'accès à courte durée de vie. Le client utilise automatiquement le jeton de rafraîchissement pour obtenir un nouveau jeton d'accès en arrière-plan, de sorte que les utilisateurs n'ont rarement besoin de se reconnecter à moins que leur session n'ait été explicitement révoquée.
</Info>

## Résoudre les erreurs 401

Une réponse `401 Unauthorized` signifie que le serveur n'a pas pu authentifier votre requête. Les causes les plus courantes sont :

| Cause | Solution |
| --- | --- |
| Jeton expiré | Rafraîchissez votre session et réessayez avec le nouveau jeton |
| Jeton manquant dans l'en-tête | Assurez-vous que l'en-tête `Authorization: Bearer <jeton>` est présent dans chaque requête |
| Non connecté | L'utilisateur doit compléter le flux de connexion XERA1 avant de faire des appels API |
| Format d'en-tête incorrect | Le schéma doit être exactement `Bearer ` (B majuscule, un espace) suivi du jeton |
| Mode `credentials` manquant | Pour les appels `fetch` du navigateur qui dépendent des cookies, ajoutez `credentials: 'include'` aux options |

Si vous continuez à voir des erreurs `401` après avoir rafraîchi le jeton, la session de l'utilisateur a peut-être été révoquée. Dans ce cas, redirigez-le vers la page de connexion XERA1 pour démarrer une nouvelle session.

<Warning>
  N'exposez jamais votre jeton d'accès dans du code source côté client, des dépôts publics ou tout emplacement visible par d'autres utilisateurs. Traitez-le comme un mot de passe : stockez-le uniquement en mémoire ou dans un stockage de session sécurisé et non public. Si vous pensez que votre jeton a été compromis, déconnectez-vous immédiatement de XERA1 pour invalider la session.
</Warning>
